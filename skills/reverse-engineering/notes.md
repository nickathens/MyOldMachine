# Notes: reverse-engineering

Append-only learning notes from usage. Edge cases, gotchas, better approaches.

[2026-10-12] A library ABSENCE claim from grepping a package name is a false negative on minified bundles: minifiers strip package names. A real scan searched 'framer-motion'/'framerMotion', found 0, and the first dossier wrongly said no Framer Motion; its internal string 'framerAppearId' (optimizedAppearDataAttribute) was in 2 of 17 chunks. Use strings that survive minification (string literals, property names, Turbopack export lists) and prove each marker on a known positive before trusting a zero.
[2026-10-12] Watch before reading, and keep an idle control for every driven run. The first Supreme dossier kept the question's premise (scroll drives the reel) and credited 34 ?_rsc= requests to scrolling; watch_page showed the document is one screen tall, the wheel and arrow keys change nothing (15 vs 15 changes against the idle run), and an idle capture_net load fires the same 34 requests. Run the idle capture and watch_page --control first, then read the code for the numbers the run showed (1e4, duration-[800ms], aria labels).
[2026-10-12] libscan markers are only as good as their proof: when prove.py disagrees with an expectation, read the sample before changing either. Locomotive Scroll 5's published UMD takes Lenis from outside (require('lenis') or a global) and carries none of it, so the expectation was wrong, not the marker. Real-site corroboration found no false library on 16 sites; misses were pages that do not load the library (plyr.io is a deprecation notice, embla's home loads only package metadata; its /docs/examples/predefined page runs Embla 9 rc04) or versions outside coverage (pixijs.com header runs an ancient Pixi).
[2026-10-12] Joining marker strings with ', ' collided with a real marker (anime.js 3's 'easeOutElastic(1, .5)'), which would have split it when validate_dossier --evidence re-read the claim. The joiner is now ' | ' and a test asserts no marker contains it. Any delimiter a check splits on needs a guard over the real data, not just the sample.
[2026-10-12] wabt prints the same bytes with different operand text by version: 1.0.36 (sandbox tools image) numbers a function's locals after its parameters (local[3..25]); Ubuntu's 1.0.34 printed local[1..23]. Cite file offsets and bytes from --disasm, never the operand text. wasm-decompile in both versions names params a, b in the signature and i, n in the body.
[2026-10-12] Hidden string tables (javascript-obfuscator) need the code's own decoder to run: wakaru leaves them hidden, webcrack (isolated-vm) recovers them. So --deobfuscate runs webcrack only inside sandbox.py's docker --network none container. webcrack -o writes deobfuscated.js; read that file, never the container's stdout, which sandbox.py keeps only as a 200 KB tail.
[2026-10-12] MutationObserver batches can hold several records for the same attribute; comparing each record's oldValue against the LIVE attribute double-counts (class 'a'->'a b'->'a c' read as +c twice, b never added). Chain each record's new value to the next record's oldValue for the same target and attribute (watch_page.py, regression test test_two_writes_in_one_batch_are_told_apart).
[2026-10-12] An input test proves nothing until you know what received the input. Playwright's pointer starts at the page's top-left corner, so watch_page's first Supreme wheel test landed on the site header, outside the reel, and beh-input-ignored was marked confirmed on it (found on audit 2026-10-12 by reading the input record's node in the saved run). The pointer now rests at the viewport centre in every run (moved before the settle, so hover effects happen in the control too) and compare() lists received_by. Read received_by before trusting any 'no change'.
[2026-10-12] A case-blind URL pattern like //[^\s"']*gsap[^\s"']* reads random base64 as a library: inline images and fonts are long runs of URL characters full of '//', and a case-blind 'gsap' turns up about once per megabyte of random base64 (blobs of 200 and 400 KB both tripped it in testing). fingerprint.py reported GSAP (strong) from random image data, and the unbounded run made the scan quadratic (48 s on a 2 MB blob). Bound the URL run ({0,300}) and make a short name start a path segment ([/@.]gsap\b). Test every text pattern against random base64 as well as against real pages.
[2026-10-12] Ghidra 12 dropped Jython: a headless .py postScript fails with 'Ghidra was not started with PyGhidra. Python is not available'. Write the postScript as a Java GhidraScript (GhidraDecompile.java); headless Ghidra compiles and runs it with the bundled JDK, no PyGhidra install, no network. analyzeHeadless options proven: -import, -postScript, -scriptPath, -deleteProject, -analysisTimeoutPerFile; JVM heap is set by the env var GHIDRA_HEADLESS_MAXMEM (default 2G), not a CLI flag.
[2026-10-12] A JVM in a docker --network none container dies at startup with java.net.UnknownHostException on its own random hostname (getLocalHost needs a resolvable name and there is no DNS). Fix: run the container with --hostname localhost, which resolves from /etc/hosts offline and does not weaken the network isolation. Added as sandbox.run(hostname=...).
[2026-10-12] binwalk only IDENTIFIES by itself; -e extraction shells out to unzip/7z/xz/etc, so the re-carve image must carry the free extractors or extraction finds signatures and writes 0 files. Also binwalk's extractor calls pwd.getpwuid(os.getuid()) and crashes KeyError when the container has no entry for the host uid; mount a minimal /etc/passwd+/etc/group for the uid (sandbox.run with_passwd=True). Debian trixie ships binwalk 2.4.3 (Python), not the Rust 3.x.
[2026-10-12] bin_triage Mach-O endianness is easy to invert: the non-swapped on-disk magic (FE ED FA CE/CF) is a BIG-endian file; the byte-swapped magic (CE/CF FA ED FE) is LITTLE-endian, which is every Intel/Apple-silicon binary (the common case). A synthetic Mach-O header test (hand-packed, known cputype) caught the inverted check where corroboration could not, because there is no real Mach-O on this machine. Build synthetic headers with known fields for any format you cannot corroborate against a real tool.
[2026-10-12] radare2 JSON keys for a driver: aflj keys a function's address as 'addr' (NOT 'offset'); reading 'offset' silently prints 0x0 for every function. pdfj ops carry addr, bytes (hex), opcode, size. izzj returns {strings:[...]} or a bare list depending on version; normalise both. Drive r2 one command at a time (r2 -q -c '<cmd>' file), parse the JSON from stdout; simpler and more robust than marker-splitting several cmdj outputs in one run. Restrict any symbol argument to a bare name or 0x-address so ';' cannot inject an r2 command.
[2026-10-12] A sandbox's OUTPUT is untrusted on the way out: the tool inside runs as our uid with /out writable, so a compromised one can leave a symlink to any host file (or a FIFO, which blocks the host's open forever) where its result belongs. ghidra.py read /out/result.txt with plain open() and returned a planted link's target as 'decompiled C'; wasm_inspect shutil.move()d the link into place as --wat-out; unminify copytree() followed links. Read back only via sandbox.open_output (realpath equals the lexical path, O_NOFOLLOW|O_NONBLOCK, S_ISREG) or copy_output_tree, and never move a container file (a moved link is still a link). Test with a fake sandbox.run that plants the link: no container needed.
[2026-10-12] requests reads a redirect's whole body, and gunzips it, before following the Location, EVEN with allow_redirects=False: Session.send builds response.next by consuming it. 597 KB of gzip in a 302 cost 618 MB RSS; any stream=True cap on the final page is irrelevant. Measure with tracemalloc (it sees urllib3's decoded bytes). Fix (webfetch.py): prepare the request and call session.get_adapter(url).send(req, stream=True, **session.merge_environment_settings(...)) yourself, extract_cookies_to_jar, close redirects unread: 0 MB, cookies kept.
[2026-10-12] A radare2 name filter that allows '@' lets commands through: r2 reads '@@' as a foreach iterator and '@@c:CMD' runs CMD, so 'entry0@@c:ij' (letters, digits, '@', ':') ran 'ij' (its JSON came back as: Invalid number '{"core":{"type":"DYN'). No r2 function name on /bin/ls carried '@' or '$'. And assertRaises(R2Error) on r2.disasm passed even while an injected command ran, because radare2 printing no JSON raises R2Error too: match the refusal's message, or test the filter function directly.
[2026-10-12] Three-byte file magics fire on ordinary data: JPEG FF D8 FF and gzip 1F 8B 08 each hit about once per 16 MB of random or compressed bytes (8 false 'embedded files' in 64 MB). Validate the structure after the magic (JPEG: marker byte, then a segment length that lands on the next FF; gzip: FLG top bits clear, XFL in 0/2/4, OS <= 13 or 255; bzip2: BZh + block digit + '1AY&SY'). 'BZh91' alone missed every bzip2 not packed at block size 9. And a per-signature hit cap must set truncated: 300 PNGs came back as 256 with truncated False.
[2026-10-12] Regexes over hostile HTML: any pattern that runs from an opener to a far terminator ('<script[^>]*', '(.*?)</script>', '<link[^>]*rel...[^>]*>') is quadratic or worse on a page of unclosed openers: 160 KB of '<script ' took libscan 57 s (hours at its 20 MB cap), '<script type="module" ' took fingerprint 14 min at 5 MB, and the '<link rel=preload ' case did not finish in 20 min. Walk tags in one pass (find the opener, find its first '>', continue after it; inline script content to '</script'), or bound every [^>] run. Time each pattern on 20 MB of each opener repeated.
[2026-10-12] A chunked scan with an overlap and dedup-by-offset still cuts strings: the window that sees a string first reports it cut at the window edge, and the later whole copy is dropped as 'already seen'. Python's re works on an mmap (and memoryview) in place, so finditer over the whole buffer with a bounded quantifier {min,8192} needs no chunks at all.
[2026-10-12] A per-read timeout is not a deadline: requests/urllib3 apply timeout= to each socket read, so a server sending one byte inside each timeout never lets a download end, body or headers (a 1 s timeout was still reading after 10 s; 5 MB at 5 B/s is 11 days). webfetch.get now arms a SIGALRM ITIMER_REAL deadline (180 s, main thread only) and raises a custom Exception subclass, not TimeoutError/OSError, so no requests or urllib3 layer catches it as its own. urllib3 read1() is no fix: with decode_content it loops inside itself while a gzip stream decodes to nothing.
[2026-10-12] Cap entry COUNTS, not just bytes, in any parser of an untrusted container format: a 3 to 4 byte wasm vector entry becomes a Python dict of hundreds of bytes, so 3 MB of empty imports took 574 MB (190x) and ~42 MB of module would have OOM-killed the bot's 8 GB cgroup. The earlier audit's mmap fix (no copies of section bytes) did nothing for this. Measure with tracemalloc on a flood of the smallest legal entry for each vector.
[2026-10-12] sandbox.run keeps a 200 KB TAIL of stdout, which is right for logs and wrong for a tool whose data IS stdout: every radare2 list (aflj, izzj) from a mid-sized binary failed to parse (python3.12, 8 MB: 1.1 MB of functions, 8.8 MB of strings). The tests only used /bin/ls, whose lists fit. Pass max_output and check stdout_cut; and test any output path on an input big enough to cross every cap on the way out.
[2026-10-12] A docker run's time limit enforced only by the Python caller dies with the caller: kill -9 the client and the container keeps running to its natural end (19 s into a 10 s limit, measured). Wrap the command in coreutils timeout inside the container as well (every image here is Debian-based and has it), a few seconds after the caller's limit.
[2026-10-12] Source map recovery: webpack names colliding modules 'path?hash' (devtoolFallbackModuleFilenameTemplate), so stripping the query makes two sources one path and the second silently overwrote the first while reporting 2/2. Also 'src/a' plus 'src/a/b.js' cannot both exist; that OSError once ended the whole recovery and was reported as 'no usable sourcesContent'. Dedupe with ~2 before the extension and skip-with-reason on OSError.
[2026-10-24] Running a tool that mis-handles RLIMIT_FSIZE: the .NET runtime takes SIGXFSZ (rc 150->128+22, or a 'dumped core' from the inner timeout) under a --memory cgroup when sandbox.run sets --ulimit fsize for max_write. Fix: sandbox.run has fsize_cap (default True); pass fsize_cap=False for a .NET tool (csharp.py project write) and rely on the directory-poll cap. gcc, radare2, ghidra, binwalk are fine with the fsize rlimit.
[2026-10-24] strace in the locked sandbox needs NO cap-add: strace traces its own child (PTRACE_TRACEME), which succeeds under --cap-drop ALL + default seccomp + non-root (ptrace(0,0,0,0) returns 0). trace.py runs this way. CAP_SYS_PTRACE is only for attaching to an existing or cross-uid process.
[2026-10-24] Godot pack format is v4 as of 4.7 (not v2): magic GDPC, then format_version=4, engine maj/min/patch, pack_flags, u64 file_base, u64 dir_offset, and the directory lives at the END of the file (file data in the middle). v2 (Godot 4.0 to 4.4, NOT Godot 3) has no dir_offset and 16 reserved u32 with an inline directory; Godot 3 writes v1 (no pack_flags, no file_base, no per-file flags, ABSOLUTE offsets). Confirm a format against the source of the release that writes it, not memory and not the newest loader: core/io/file_access_pack.{h,cpp} at each tag (3.6: 1, 4.0 to 4.4: 2, 4.5 and 4.6: 3, 4.7: 4). The per-file flags u32 and pack_flags/file_base are read for versions >=2. (Corrected 2026-10-24: this line first called v2 'Godot 3', read off the 4.7 loader alone, and the reader refused every real Godot 3 pack.)
[2026-10-24] GDRE Tools (gdsdecomp 2.7.4) exits 0 when --decompile FAILS ('Error: failed to decompile', no output file), and --version exits 1 while printing the version. Judge success by the output file, never the exit code; gdre.py does. --decompile needs --bytecode (an engine version like 4.7.2 is fine: GDRE maps it to the newest table at or below, 4.7.2 maps to 4.5.0-stable, 3.6.3 to 3.5.0-stable); an unknown version (9.9.9) SEGFAULTS it (rc 139). --bin-to-txt keeps the input's file name and extension (a text file called x.scn) and gives a scene in its raw _bundled form; --recover writes the editor's [node] form. GDRE finds a pack by content: .pck, .bin, an exe with the trailer, no extension all list the same.
[2026-10-24] Godot 4 '--export-pack' needs NO export templates (only a full game export does: the pack-only branch in editor_node skips can_export). So a real compiled .gdc for any 4.x (and Godot 3 '--export-pack' too) comes from the editor alone; the 700 MB template download I once said was needed was not. But a binary-token export only TOKENIZES, it never parses: a probe script with a semantic error exports fine. Load each probe under its own engine (a --script harness) before trusting it as a fixture.
[2026-10-24] Behaviour harness traps from the GDRE proof (2026-10-24): (1) Godot's bytecode compiler merges equal constants inside one function and hashes -0.0 and 0.0 alike, so the ORIGINAL program also used +0.0 where both appeared, and a decompile that lost the sign of -0.0 ran identically; read constants from script.get_script_constant_map(), not from inside a function. (2) var_to_bytes of a NodePath carries uninitialised padding bytes after each name, so the same value encodes differently run to run (a false difference on Godot 4.6.2); print a NodePath with str(). (3) Give every comparison a planted change it must see on each run (prove.py's '- 99'), or a pass proves nothing.
[2026-10-24] Attribute a recovered-scene difference before blaming the decompiler: Godot 4.4's Label has no theme_override_styles/focus (4.6+ does), so the 4.4.1 editor DROPPED that property and its now-unused ext_resource when it converted the scene to binary at export; GDRE recovered exactly what was stored. Read the stored form first (gdre.py --member on the exported .scn shows its 'names' list), and in a probe use only properties every target engine has (Panel's theme_override_styles/panel).
